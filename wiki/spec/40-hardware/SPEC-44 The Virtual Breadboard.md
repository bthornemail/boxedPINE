# The Virtual Breadboard

## Definition

The virtual breadboard is the four discrete-transistor XOR builds (5T, 6T, 8T, 10T) run in a browser. Two web primitives split the work:

| Primitive | Carries | Breadboard part |
|-----------|---------|-----------------|
| `AudioContext` | the signal: every net is an audio-rate signal | wires, transistors, VCC rail |
| `<canvas>` | the geometry: where each net, gate and LED sits | the board, the sourcemap |
| `AnalyserNode` | the reading: what an observer sees on a net | the multimeter probe |

The audio graph does the computing. The canvas only draws what the analysers read. The page never computes XOR in JavaScript to light an LED.

The circuits are not hand-wired. One **description** (rules plus netlists) generates the grammar, the audio graph, the canvas layout, the sourcemap and the self-test. Editing the description and pressing *Regenerate* rebuilds all five. That is the self-generating property of [[SPEC-30 The Symbol Table G]] at small scale: the grammar is data, `learn` extends it, and the implementation is regenerated from it.

## The Encoding

The same encoding as `omi-files/omi/audio/xor.mjs`:

```
bit 0  ->  +1
bit 1  ->  -1
XOR(a, b)  =  x * y
NOT(a)     =  -x
```

## The Gate Law

In the ±1 encoding every 2-input gate is affine in `{1, x, y, xy}`:

```
out = (c0 + cx·x + cy·y + cxy·x·y) / 2
```

The four coefficients are the Walsh spectrum of the gate's truth table. `learn(name, table)` computes them; nothing about a gate is hand-coded.

| Rule | Table (00 01 10 11) | c0 | cx | cy | cxy | Transistors |
|------|---------------------|----|----|----|-----|-------------|
| NAND | 1 1 1 0 | −1 | −1 | −1 | 1 | 2 |
| NOR | 1 0 0 0 | 1 | −1 | −1 | −1 | 2 |
| OR (OR-like pair) | 0 1 1 1 | −1 | 1 | 1 | 1 | 2 |
| SWITCH | 1 1 1 0 | −1 | −1 | −1 | 1 | 1 |
| NOT (output stage) | 1 1 0 0 | 0 | −2 | 0 | 0 | 1 |

Each term maps to one Web Audio node:

| Term | Node |
|------|------|
| `c0` | the VCC rail: a `ConstantSourceNode` at 1, through a `GainNode` of `c0/2` |
| `cx·x`, `cy·y` | the input net through a `GainNode` of `cx/2`, `cy/2` |
| `cxy·x·y` | a `GainNode` with `gain.value = 0`, input `x`, and `y` connected to its `gain` param: the product |
| the sum | one `GainNode` that all taps feed; it is the output net |

The constant term is the only place the rail enters. A gate with `c0 = 0` (XOR, NOT) draws nothing from VCC.

## The Four Builds

Generated by `compile()` from the default description. Transistor totals match [[SRC-08 XOR Gate Built with Transistors]] claims 2–4.

| Build | Role | Netlist | Q | LED |
|-------|------|---------|---|-----|
| 5T | read | `n = NAND(A,B)`, `o = OR(A,B)`, `node = SWITCH(n,o)` | 5 | YELLOW, sinks from `node` |
| 6T | apply | 5T, then `out = NOT(node)` | 6 | YELLOW, sources from `out` |
| 8T | eval | `n = NAND(A,B)`, `p = NAND(A,n)`, `q = NAND(B,n)`, `out = NAND(p,q)` | 8 | GREEN, sources from `out` |
| 10T | digest | `n1 = NOR(A,B)`, `n2 = NOR(A,n1)`, `n3 = NOR(B,n1)`, `n4 = NOR(n2,n3)`, `out = NOR(n4,n4)` | 10 | RED, sources from `out` |

The 8T and 10T netlists are the standard NAND-only and NOR-only XOR constructions. The 5T/6T internal topology is a gate-level reading of the source prose ("a NAND gate on the left two transistors, a switch for the middle transistors, and an OR-like gate"); the source schematics are images and were not extracted (see [[SRC-08 XOR Gate Built with Transistors]], Gap). Treat the 5T/6T netlists as **derived**, not verbatim.

### Sink and Source

An LED that **sinks** is lit when its net is low (current flows into the circuit). An LED that **sources** is lit when its net is high. This is the "LED direction is flipped" the source describes between gate 1 and gate 2. In the graph the LED level is `0.5 ± 0.5·net`, built from the rail, so it is also a signal.

## The Generated Sourcemap

`compile()` numbers transistors in netlist order and places them on row 5, every fifth column from 1. For the 8T this reproduces the table in [[SPEC-41 The 8T XOR Circuit]] exactly (Q1–Q8 at columns 1, 6, …, 36).

For the 6T it does not: [[SPEC-40 The 6T XOR Circuit]] puts Q4 at column 21 and skips 16, giving 1, 6, 11, 21, 26, 31. The generator gives 1, 6, 11, 16, 21, 26. Either the YAML leaves a gap between the switch and the OR-like pair on purpose, or the YAML has a typo. Unresolved; listed in [[OPEN-01 Open Questions]].

## The 6T Contradiction: a Proposed Reading

[[OPEN-00 Contradiction Register]] #1 records that the 6T reads as XNOR (`Atom.apply()` returns 254/255).

The breadboard reproduces this exactly. Tick *Read 6T before its output stage* and the 6T LED is wired to `node` as a sourcing LED. The self-test then reads `1 0 0 1`, which is XNOR, and the 6T row fails.

Proposed reading (**derived, not confirmed**): the 5T's `node` is active-low. It is XNOR, and the sinking LED shows XOR by inverting it physically. The sixth transistor inverts `node` in logic, so its output is XOR with a sourcing LED. An implementation that reads the 6T at `node` with source polarity reads XNOR. Under this reading `Atom.apply()` probes one transistor too early, or applies sink polarity where it should apply source polarity. This needs to be checked against `Atom.apply()` itself before OPEN-00 #1 can be closed.

## Self-Generation

```
description ──learn──▶ grammar      (truth table → spectrum)
            ──compile─▶ circuits     (netlist, depth, Q numbering, sourcemap)
circuits    ──realize─▶ audio graph  (the signals)
            ──layout──▶ canvas       (the geometry)
            ──selfTest▶ verdict      (OfflineAudioContext, four vectors)
```

- `learn(name, { table, transistors, arity })` adds a rule. The rule is checked (four bits, upper-case name) and its spectrum stored.
- `compile(circuit)` rejects unknown rules ("learn it first"), nets driven twice, and nets read before they are driven.
- Regenerate is total: the old audio sources are stopped and a new graph is built from the new description. There is no in-place patching.

Example: add `"XNOR": { "table": [1,0,0,1] }` to `rules` and a circuit `[["x","XNOR","A","B"],["out","NOT","x"]]`. The page grows a fifth lane, the sourcemap grows, and the self-test passes it. Remove the rule and Regenerate fails with `net x uses unknown rule XNOR (learn it first)`.

This is scoped to the breadboard. The protocol-wide `learn` and `regenerate` in [[SPEC-61 Implementation Status]] remain unimplemented.

## The Observer

The `AnalyserNode` on a net is an observer in the sense of [[SPEC-24 Observers]]: the signal does not change; what the LED shows depends on where and with which polarity it is read. The 6T probe toggle is exactly that: one graph, two readings, XOR or XNOR.

## Sound

Each build drives a tone through a `GainNode` whose gain is the LED level (low-passed at 40 Hz to remove clicks):

| Build | Tone |
|-------|------|
| 5T | 220 Hz (A3) |
| 6T | 277.18 Hz (C♯4) |
| 8T | 329.63 Hz (E4) |
| 10T | 440 Hz (A4) |

When A ≠ B all four agree and an A-major chord sounds. With the 6T probe on, the C♯ sounds alone on A = B and drops out on A ≠ B: the disagreement is audible.

## Verification

The self-test renders each build through the four XOR input vectors (00, 01, 10, 11) in one `OfflineAudioContext` pass per build (one 128-sample block per vector, every net on its own channel). It checks the LED against `a ^ b` and every internal net against a pure-JS reference evaluation.

```bash
cd omi-files/omi/audio && npm install && npm test
```

Result on 2026-10-07: all four builds pass, transistor totals 5/6/8/10, the 6T `node` reads XNOR (`1001`), and a rule added with `learn()` compiles and passes.

The same test runs in the page on every regenerate.

## Running the Page

The page loads `kernel.mjs` as an ES module, so it must be served over HTTP (browsers block module imports from `file://`):

```bash
python3 -m http.server 8417 --directory omi-files/omi/audio/breadboard
```

Then open `http://localhost:8417`, press *Power on (+5V)* (this starts the `AudioContext`, which browsers only allow after a click), and toggle A and B with the buttons or the `a` and `b` keys.

## Limits

- Gate-level, not transistor-level. No voltages, currents, β, or propagation delay. Every net settles within one render quantum.
- The 5T/6T topology is derived from prose; see above.
- `SWITCH` has the same truth table as `NAND`. It is a separate rule only because it costs one transistor, not two.
- The 5T's "cannot forward its output" (SRC-08 claim 11) is not enforced: another circuit could read its `node`.
